# Quantization

Q5_0 first, then the other ggml blocks of 32 (Q4_0, Q4_1, Q5_1), then Q4_K_M. After those,
compare round-to-nearest, importance-weighted K-quant, and a GPTQ/AWQ-like pass where a layer
fits. The last step is file size, resident GPU memory, and warm latency against Q8_0.

Q5_0 is 32 weights, an f16 scale, and five-bit codes: 22 bytes in the file. On the GPU the codes
are repacked into weight order, 24 bytes per block, plus the f16 scale, and the GEMM, gemv, and
embed dequantize them in the kernel. The CPU decoder stores each code as `code - 16` with that
scale and uses the Q8 tile. The Neural Engine dequantizes Q5_0 to F16 at load. GigaAM's CPU
decoder still expands its weights at load, as it does for Q8_0.

Q4_0 is that same block with four-bit codes, `(code - 8) · scale`, 18 bytes. Q4_1 and Q5_1 add an
f16 minimum, `code · scale + min`, 20 and 24 bytes. The GPU keeps those codes packed and applies
the scale and the minimum in the kernel. The CPU decoder keeps Q4_0 on the Q8 tile. Q4_1 and Q5_1
expand there because of the minimum.
